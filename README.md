# Legado 阅读书源仓库

## 📖 项目介绍
这是一个开源阅读（Legado）书源整理仓库，持续更新维护。

## 📊 当前版本
- **版本**: 发布页 v3.2.23（2026-11-16 发布，assets 已验证：books.json 12.0MB + clean_rules.json 494KB。**本次为脚本加固版，书源数据未变**）
- **更新日期**: 2026-11-16
- **书源总数**: **2104 个**（2026-11-18 深度体检后：中间层清理 + 提升 235 条，再逐条复核删除 232 条问题源——脏 URL 12 / 域名废弃 53 / 端口确认不通 96 / 非小说影视站 12 / 页面确认死 45 等。成人段允许视频/漫画/影视，只剔 PPT/档案馆/网盘/社交/音乐播客这类与阅读无关的站）
- **净化规则**: 1176 条配套净化
- **静态内容站豁免**: 古籍/国学/诗词/典籍类站点内容固定，"最后更新停在建站时"是常态而非失活，两道门槛都豁免判死（实测国学经典站被 deep 判僵尸，实为正常的 Cloudflare 403 古籍站）
- **门槛挡掉项可追溯**: 摘要 `gates.*.dropped_items` 每项含 `name` + `url`，不再只是名字（同名变体多，光看名字认不出是哪个站）
- **源质量四层体检**: `scripts/quality_check.py` 不依赖搜索接口（full 校验遇反爬 57% 判不出），分四层独立判：URL 格式 → DNS → 端口 → **首页内容**。第 4 层专治「域名活着但已经不是小说站」——实测抓出 12 个名字叫「全本小说」「完结小说」、首页却是影院/直播的源。**网络层初判必须 `--recheck` 复核**（实测端口层误判 56%、死页层 63%）。详见 `docs/源质量四层体检.md`
- **中间层不堆僵尸**: `url_key` 比对时抹平尾斜杠与 host 大小写（`clean_url` 不做这件事，`https://a.com` 和 `https://a.com/` 会被当成两个源）。`stage_daily` 写盘前剔除"已在正式版"的条目——实测 370 条里有 120 条（32%）是这种残留
- **上游校验标记不丢**: 合集作者会把做题结果写进分组名（`校验可用`、`2026年11月07日搜索校验`、`🌹已检26.10.15`、`【❌❌】搜索正文失效`）。整理阶段会重写 `bookSourceGroup`，这些标记原本一进正式版就没了（实测 2105 条里一条都查不到）；现在覆盖分组前先抄进 `comment`（`// 上游:校验可用`），幂等不覆盖已有健康度标记。中间层 304 条里 53 条（17.4%）带这类标记
- **模板日期识别**: sitemap 的 `<lastmod>` 未必是真实更新时间——同一批里同一个 lastmod 出现 ≥3 次就视为模板假数据、整组放行（实测爱丽丝书屋 4 个镜像共用 `2024-08-19`，而 4 个站 HTTP 200、66KB 内容照常在服务）。单站看 lastmod 完全看不出这件事，必须横向比。只统计"已超过 180 天"的日期（模板判定的目的是防误删，新鲜日期本来就不删，标进来只会污染报告）
- **双证据同向才判死**: deep 门槛必须"首页日期"和"进站日期"都超过阈值才允许删站。首页日期取不到（`home_days=None`）时**放行**——拿不到证据不等于没有矛盾证据（实测 6 条候选因此被误删，其中 4 个站 HTTP 200 在正常服务）
- **中间层阶段实况**: `stage_daily` 写 `weekly/stage_report.json`，摘要的 `stage` 字段能直接看到"今天从合集抓回多少 / 被黑名单拦掉多少复活源 / 真正新增多少"，同样不用扒 CI log
- **门槛实况**: 两道门槛各写一份 report（`weekly/health_gate_report.json` / `weekly/deep_gate_report.json`），`daily_summary` 读进来写进摘要的 `gates` 和 `gated_out`——摘要里能直接看到"今天体检了几个、挡掉几个"，不用再去扒 CI log
- **所有落盘原子写**: 常数与断点统一走 `utils.dump_json`（先写 `.tmp`、`fsync`、再 `rename`）。流水线被 kill 或磁盘打满时，普通 `open("w")` 会留半截 JSON 把下游带断；实测写完前 SIGKILL 打断，旧文件仍完整可解析
- **时间预算是硬上限**: 两道门槛原用 `with ThreadPoolExecutor` + `break`，`with` 退出会 `shutdown(wait=True)` 等所有已提交任务跑完，`--budget` 形同虚设（单站最坏 42s，10 并发能把 180s 拖成 240s+）。现改为 `as_completed` + `cancel_futures` + **deadline 下推到 worker**（排队任务超时直接返回"跳过"）+ 超预算落盘后跳过解释器线程 join：`--budget 2` 实测 **72s → 3.3s**
- **纯函数单测**: `tests/test_core.py` 14 项 + `tests/test_gate.py` 13 项。前者覆盖 `_split_index` 的 `class.xxx.N` 拆分、host 归一化（`m.hongxiu.com` → `hongxiu.com`）、静态站豁免；后者专门测"什么情况下**不许**删站"（首页日期缺失放行、双证据矛盾放行、大厂/静态站豁免、模板日期识别、dry-run 不落盘）。审计 E4 会实跑测试，不再只是"字符串还在不在"——把断言故意改坏会让审计 FAIL
- **剔除黑名单**: `excluded_sources.json`（62 条）。从正式版删掉的源会被下次采集从合集里重新抓回来，`stage_daily` 读这份清单拦截：整站无关的（PPT素材/网盘/档案馆/社交/音乐播客/有声/空壳）按域名拦，僵尸站只按精确 URL 拦（不误伤同站仍在用的其他规则）。成人段的视频/漫画/影视站不在此列

## 🔍 校验流程
校验分两档（2026-11 用户明确要求）：

| 档位 | 时机 | 内容 | 特点 |
|------|------|------|------|
| **快速存活**（quick） | 采集池第一遍（`--collect` / `validate` 默认） | 首页可达性 + WAF 识别，快速剔除死站 | 量大也能几分钟跑完 |
| **完整真实性**（full） | **发布前**（`--publish-pending` / `validate --full` / `final --publish`） | 存活 + 搜索/发现至少一项可用 + 全部过滤规则 | 一步不少，慢但发布必跑 |

发布前完整执行以下校验（一步不少）：

1. **基础结构校验**：必填字段、URL 格式、域名去重
2. **网站存活校验**：首页可达性（WAF 盾站 403/405/503 不淘汰）
3. **真实性校验——搜索/发现至少一项可用**（2026-11 新增，解决"网站活着 ≠ 书源有效"）：
   - **搜索**：通用关键词轮试（我的/天下/重生/总裁/王爷/系统/都市/修仙/神/爱），用书源自身 `ruleSearch.bookList` 规则**真实解析 HTML**，解析出 ≥1 本书才算可用
   - **发现**：`exploreUrl` 前 3 个入口轮试，用 `ruleExplore.bookList` 解析，**至少 1 个入口解析出书才算可用**（发现页按钮至少一个能用）
   - **判定**：搜索或发现任一可用 → 保留；两者都解析不出 → 淘汰（识别"域名还在但内容已换/域名挂售"的失效源）；网络/反爬无法判定 → 保留待验
   - **成人源按实际情况校验（宽松豁免）**：成人组混有漫画/短剧/影视/图片/听书站，本来就没有"书名"可解析，拿书籍规则硬卡必然误杀。改为判"至少有一条能取内容的规则链"（正文/目录/搜索/发现任一条非空）→ 可用保留；四条全空的空壳规则才淘汰；死站仍照常淘汰（失效不保留）
   - 12 个大厂源永不淘汰（反爬环境判定不可靠，阅读器端可用）
4. **规则完整性校验**：详情/目录/正文规则完整性
5. **垃圾过滤**：非小说/测试/失效标记剔除；**成人内容一律保留**（含成人漫画/影视等非小说类），成人组排序最末、豁免改名与符号清理

> 发布（`--publish-pending`）时同样全量执行上述校验，一步不少。

## 🤖 自动采集脚本
本仓库内置全自动采集脚本 `autocollect.py`，可一键采集、校验、合并书源。

### 数据源池
- yckceo.com 书源列表（前10页最新上传的源，每页100个）
- yckceo.com 书源合集（列表前30个大佬整理的合集，每个合集含数百个源）
- 2个直链大佬仓库（酷安三舞313/关耳女频；原XIU2精品与shidahuilang已于2026-11失效：71e564f.json 404、shidahuilang/shuyuan 被GitHub以tos封禁）

### 自动更新
- **采集层**：GitHub Actions 每天自动采集+清洗（跨洋已优化：30s超时+20并发+重试），结果 push 到 `weekly/cleaned_*.json`，全程无人值守
- **中间层**：云端每日把当天 cleaned 里**「正式版和中间层都没有的新源」**并入 `books_pending.json`（只新增、不重排，不碰正式版）；探活只判确定性死站（404/410 与域名不存在），403/405 WAF 站、429、5xx、超时一律保留
- **正式版**：确认后把中间层提升为 books.json + clean_rules，**发布前自动跑完整真实性校验（full，一步不少）**，并自动发新版本 Release（vX.Y.Z patch+1）
- **断点续传**：采集/清洗/校验全链路支持中断恢复——校验每批落盘 checkpoint（`raw/autocollect/ckpt_*.json`），对话中断或沙箱重置后重跑同一命令自动跳过已验源，只补未验部分（详见 DEVELOPMENT.md 断点矩阵）

> ⚠️ 采集与校验分离的原因：GitHub Actions 免费 runner 位于美国，访问国内站点**采集**已通过加大超时+并发+重试跑通（实测单请求 2-3s）；但**存活/搜索校验**针对国内书源站点，跨洋会大量误判（合格率 72%→27%），因此校验必须在国内网络执行。

### 三层架构（采集 → 中间层 → 正式版）
```
采集层（GitHub Actions 每日自动，双 cron 18:07/22:07 北京时间）   中间层        正式版
列表全量+合集+大佬仓库 → 清洗去重 → weekly/cleaned_*.json（artifact 保留 35 天）
                                                        ↓ 当天自动
只取「正式版与中间层都没有的 URL」→ 确定性探活(404/410/DNS 死才淘汰) → 垃圾过滤
                                                        ↓
                                    追加进 books_pending.json（只新增不重排，待确认）
                                                        ↓ 发布前（每月自动或手动）
books_pending.json 完整真实性校验(full，一步不少) → books.json + clean_rules + Release 新版本
```

### 使用方法
```bash
# ① GitHub Actions 每日自动：采集+清洗 → artifact（cron 每天 UTC 17:07 = 北京 01:07）

# ② 中间层由云端每日自动追加（scripts/stage_daily.py）。本地也可手动补一次：
python3 scripts/stage_daily.py --cleaned weekly/cleaned_XXX.json

# ③ 本地：确认后把中间层提升为正式版并发布（发布由你确认）
python3 autocollect.py --publish-pending --publish

# 一键（cron 每日自动）：采集 → 清洗 → 并入中间层（quick 存活校验，不发布）
bash scripts/run_daily_collect.sh 1

# 或手动分步执行（每步独立落盘、可断点恢复）：
python3 scripts/collect_staged.py list --months 1      # A1: 采集yckceo书源列表前10页
python3 scripts/collect_staged.py heji 1 1 --months 1 --limit 30  # A2: 合集只采列表前30个（每个含多源）
python3 scripts/collect_staged.py gurus                # A3: 2个存活大佬仓库直链
# 以下为早期手动分片流程（备用路径，主流程走 autocollect.py）：
python3 scripts/run_from_fragments.py clean            # B: 流式合并清洗去重(checkpoint)
python3 scripts/run_from_fragments.py validate --start 0 --count 1000   # C: 分批快速存活校验（发布前用 --full 切完整真实性）
python3 scripts/filter_junk_sources.py                 # D: 垃圾过滤(成人单独分组)
python3 scripts/run_from_fragments.py final --input raw/autocollect/validated_clean.json --publish  # E: 整理+发布（--publish 时自动跑发布前 full 复检）

# 单命令完整流程（适合交互调试，沙箱环境可能中断）
python3 autocollect.py --publish --months 1
```

### 优化特性
- **增量采集**：`--months N` 按更新时间过滤，只采集最近N个月的列表/合集，超范围自动停止翻页
- **两级过滤**：快速连通性过滤 + 完整搜索测试（3关键词），节省时间
- **域名去重**：同一站多域名自动合并，保留最优规则
- **WAF友好**：403盾站不淘汰，能搜出书就保留
- **大厂保护**：12个正版大站单独保护，任何环节不被覆盖
- **垃圾过滤**：剔除失效标记/测试占位/非小说，成人内容单独归组
- **自动报告**：每次跑完生成采集报告，采集/清洗/淘汰/入库一目了然
- **断点恢复**：采集分片独立落盘、清洗checkpoint、校验分批追加，中断零损失
- **跨洋优化**：超时/重试/并发可环境变量调节（YCKCEO_TIMEOUT/RETRY/CONCURRENCY）
- **三层隔离**：采集→中间层（待确认）→正式版，正式版不被自动更新直接覆盖

## ✏️ 命名规范
- 大厂正版保留原名（起点中文/番茄小说等）
- 其他源四字纯汉字（不足补足、无中文兜底），重名加数字

- 去掉表情符号和特殊字符
- **成人书源豁免**：保留原名原样（含特殊符号/表情），仅重名时加数字；仍参与名字族排序，整组排在最后
- 同名族聚合：同名前缀的源（笔趣阁1/2/3…）相邻排序，序号按数值递增
- **同族名字聚合排序**：组内按"名字族+数值"自然排序（笔趣阁 → 笔趣阁2 → … → 笔趣阁141 相邻且数值递增），customOrder 字段控制导入后顺序
- 分组顺序固定：大厂正版（12，手动顺序保护）→ 笔趣阁类 → 玄幻武侠 → 言情女频 → 综合其他 → 成人书源
