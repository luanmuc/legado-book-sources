# 源质量四层体检

> 起因：2026-11-18 用户质疑「2325 条还是太多，感觉里面还有死站和垃圾站，校验是不是有问题」。
> 查下来确实有问题——那一轮的 full 校验有 **57% 的源判不出（blocked）**，等于一半多没真正校验到。
> 本文记录一套不依赖搜索接口、能真判的体检方法。

## 为什么原来的校验不行

`validate_sources(mode="full")` 的判据是「能不能用书源规则搜到书」。但绝大多数站点有反爬：

| 现象 | 后果 |
|------|------|
| 搜索接口返回 403 / Cloudflare 验证页 | 判成 `blocked`（usable=None）→ **保留** |
| 首页 JS 渲染 | 抓不到书列表 → 判成不可用或判不出 |
| 站点超时 | 同上 |

结果：2336 条里 1332 条（57%）判不出，只淘汰 11 条。**这等于没校验。**

更根本的问题：**域名活着 ≠ 还是小说站**。实测发现 12 个名字叫「全本小说」「完结小说」「蚂蚁小说」的源，域名没变，但首页已经是影院/影视/直播站了——书源规则对它们完全无效。

## 四层体检（由浅入深，每层都独立可判）

### 第 1 层：URL 格式合法性（不联网，秒级）

判据：能不能解析出合法 host。

```
合法：example.com、www.example.com、纯 IP（103.188.121.74）
非法：www.xinbqg.com-1、www.b5200.net-By、www.wrlwx.commd-guaner
      www.pan5.net*、m.damaoli.com66、www.bz88888.net////、moyue://rapid
```

这类是上游数据拼接错误，**不是域名废弃，是 URL 本身就是坏的**，任何一个都解析不了。

实测 2104 条里 12 条。

### 第 2 层：域名解析（DNS，不碰 HTTP）

`socket.getaddrinfo(host, 443)` 抛 `gaierror` → 域名已废弃。

这一层**不受反爬影响**，判据很硬。实测 2325 条里 71 条解析不出（host 合法的 60 条是真空号，另外 12 条其实是脏 URL）。

> 坑：`getaddrinfo(host, 443, timeout=8)` —— getaddrinfo **不接受 `timeout` 参数**，
> 会抛 TypeError，被当成「DNS 挂了」。第一次跑就踩了这个，所有站都报解析失败。

### 第 3 层：端口连通（TCP，还是不做 HTTP）

443 和 80 各试一次，都连不上 → `REFUSED`。

实测 2325 条里 158 条域名通但端口不通。

**但这层必须复核**——抽样 8 条里就有 `m.doupocangqiong.cc` 返回 200/60KB 是活的，
说明单次 TCP 失败可能只是瞬时超时或握手被重置。

复核方法用 curl 直连、多协议、多次机会：

```bash
curl -s -o /dev/null -w "%{http_code}|%{size_download}" --max-time 10 --noproxy '*' -k -L \
  -A 'Mozilla/5.0 ... Chrome/122.0' https://host
```

结果：158 条里 **37 条其实能通**（其中 21 条是 301 重定向 → 站还活着，只是换了地址）。

### 第 4 层：内容判定（抓首页，看它到底是什么站）

这是**唯一能解决「域名活着但已经不是小说站」**的一层。抓首页前 2KB + title + keywords：

| 信号 | 判为 |
|------|------|
| 含「小说/阅读/书城/章节/完本/玄幻/修真/都市/言情/武侠」≥2 个 | 小说站 |
| 含「影院/影视/电影/电视剧/直播/博彩/商城/招聘/论文/模板」≥2 个 | **非小说** |
| 页面里 `/book/`、`/novel/`、`/read/` 这类书链接 ≥5 个 | 小说站 |
| title 是 `Verifying...` / `Just a moment` / Cloudflare | **反爬墙，是活站，必须保留** |
| title 是 `404` / `Welcome to nginx!` / `Error` / `网页无法访问` | 死页/空壳 |

### 第 5 层（补充）：内容判定也要复核

「标题是 404」这一层同样会误判——`顶点中文4 www.ddsge.com` 首页 title 抓到 404，但 curl 直连返回 200/29KB 是活的（那个 404 只是某个路径的状态）。

E 类 121 条复核后：**76 条其实能通，只有 45 条确认死**。

## 复盘：四层的判准率

只有**逐层做、每层都复核**，才敢删。

| 层 | 初判 | 复核后确认 | 误判率 |
|----|------|-----------|--------|
| URL 格式 | 12 | 12 | 0（不联网，最硬） |
| DNS 废弃 | 60 | 53（7 条是脏 URL 重复计） | 低 |
| 端口不通 | 158 | 96（37 条其实能通、21 条是 301） | **56%** |
| 死页标题 | 121 | 45（76 条其实能通） | **63%** |
| 非小说内容 | 12 | 12 | 低（title 很明确） |

**结论：网络层的初判极不可靠（误判率 56%-63%），必须复核；DNS 与 URL 格式这两层最硬。**

## 仍然判不出的部分（诚实记录）

- **485 条首页抓不到内容**（超时/被墙/反爬），既不能判活也不能判死
- **663 条「未知」**：首页能打开但没抓到小说特征词，可能是纯 JS 渲染站（书列表在 JS 里），也可能真是别的站

判断：**这部分保持现状，不为删而删。** 名称与分组是《阅读》App 里用户唯一能看到的标识，至少这些源的名字还在小说范畴内；真正的「名字是小说、内容是影院」的 12 条已经清掉。

## 第六层：顽固站点的突破（2026-11-18 追加）

第一版体检后还剩 976 条判不出（抓不到 313 + 未知 663）。用户要求「想办法解决」。

### 突破手段（实测有效）

| 手段 | 原理 | 实测效果 |
|------|------|---------|
| **换路径到分类页/排行页** | 首页可能有 JS 首屏或广告墙，但 `/sort/all/1/`、`/top/`、`/list/`、`/quanben/` 是纯列表页 | 一条就突破：`www.biqudu.tv` 的 `/sort/` 返回 200 且含 7 个书链接、16 个书名链 |
| **换 Googlebot UA** | 很多站对搜索引擎放行（要 SEO 流量），对普通 UA 挡 | 纵横中文 `m.zongheng.com` 用 bot UA 直接拿到 179 书链、126 书名链 |
| **换 iPhone UA** | 部分站对移动端有独立入口 | `www.bqg36.com`、`wanben` 一类靠这个突破 |
| **http / https 都试** | 有的站只配了一个 | 常见 |

组合策略：3 种 UA × 2 种协议 × 6 个路径，**任一成功立即停止**。

### 判定「是小说站」的新判据（比关键词更硬）

分类页/排行页上一定有书名列表，所以用**链接密度**判：

```python
书链接数 = len(re.findall(r'href=["\'][^"\']*(?:/book/|/novel/|/read/|/txt/|/\d+_\d+/|/\d+/\d+/)', html))
书名链数 = len(re.findall(r'>[^<>\s]{2,20}</a>', html))
```

只要 `书链接 ≥3` 或 `书名链 ≥15`，就是小说站——这比看 title 里的词可靠得多。

# 第五层：真浏览器截图判定（2026-11-19 新增）

> 正式脚本：`scripts/shot_check.py`（原 `tmp/shot_render.py` 已提升入库）
> 流水线：`quality_check.py` 跑完自动落 `pending_for_browser.json` → `shot_check.py --pending`

四层体检的前提是"用 HTTP 客户端探内容"。当站点做了 TLS 指纹识别或 JS 挑战时，
这个前提会整体失效——**同一批站会被系统性误判为"判不出"**。

## 一、为什么必须加这一层

360 条被判"判不出"的源，TCP 全部连通（443:308 / 80:52），只是内容层拿不到。
上 Playwright/Chromium 真浏览器逐条打开后，立刻推翻两个结论：

| 站点 | 脚本结论 | 截图实际 |
|---|---|---|
| `www.sobiquge.net` | HTTP 403 → 判不出 | **完整笔趣阁**：分类导航 + 人气榜 + 172 个书链 |
| `www.shumilou.co` | 无书链 → 空壳候选 | **完整书迷楼**：封面墙 + 三栏分类书单 |

**结论：403 / 超时 / 渲染超时都不能判死。判定必须以"真浏览器渲染出的页面"为准。**

## 二、执行方式

```bash
python3 raw/autocollect/tmp/shot_render.py --start 0 --end 360
# 90s 超时 / 8 并发 / 整页截图 / 逐条落盘 shots_meta.jsonl
```

- 截图存 `raw/autocollect/tmp/shots/<idx>_<host>.png`
- 元数据存 `shots_meta.jsonl`（status / final_url / title / books / links / err）
- 360 条实测 584s

## 四、不能判死的三类（必须保留）

1. **403 / 401 / 429 / 宝塔防火墙 / Cloudflare 挑战** —— 反爬，不是死
2. **API 接口域名**（`api.*` / `quickapi.*` / `/api/v1/`）—— 首页为空是正常的，它本来就不是网页
3. **502 / 504 / 连接超时** —— 网关或临时故障

## 五、`Loading https://xxx/?tr_uuid=` 是什么

约 27KB 的纯 JS 跳转壳，浏览器渲染完仍停在 Loading，curl 也只拿到这段壳。
跳转目标通常是广告落地页 → 按死站处理。

## 六、直连复检（绕过代理）

代理会污染判定。复检一律：

```bash
curl -sS --noproxy '*' -m 12 -k -L -A '<Chrome UA>' -w '%{http_code} %{size_download} %{url_effective}' <url>
```

本轮 158 条"打不开"里，直连救回 7 条（`quanben-xiaoshuo.com`、`quanwenyuedu.io`、
`m.suixkan.com`、`m.yueyouxs.com`、`sma.yueyouxs.com`、`n.cmread.com`、`m.bqg222.com`）。
