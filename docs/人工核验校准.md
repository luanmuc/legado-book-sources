# 人工核验校准（2026-11-19）

记录第一次"用户亲自逐条进站"的完整结果，用来校准脚本判活的能力边界。
这类数据只此一份，比任何机器判据都硬。

## 一、样本与结果

360 条经截图法判"判不出"的源，经浏览器截图 + 直连复检后降到 158 条盲区，
最后由用户**亲手逐条点开**判定（156 条有结论，2 条未标）。

| 判定 | 条数 | 占比 |
|---|---|---|
| 能看小说 | **6** | 3.8% |
| 打不开/要验证 | **143** | 90.5% |
| 不是小说站 | **7** | 4.4% |
| 未标 | 2 | — |

**能看的 6 条**：bqg36、piaotian、wechat.idejian、idejian、ysfwxc、
androidv2.hongshu。

这个 3.8% 是这套判据最重要的一个数字：说明"判不出"这一档**基本等于死站**，
但仍有约 4% 的真活站藏在里面，所以不能整批无脑删除。

## 二、脚本判活的边界（三条实证）

### 1. HTTP 状态码完全不可信

- `www.sobiquge.net` 脚本 403，浏览器打开是**完整笔趣阁**：分类导航齐全、
  172 个书链、标题「笔趣阁_无广告小说_全本小说资源阅读网」。
- 反过来，143 条脚本能连上 TCP 的源，用户点开 90% 打不开。

结论：**403 既不能判死，200 也不能判活**。判死必须要有"内容层证据"。

### 2. 判死只有一类证据算数：已变性质

可判死的证据只有三种，都要看得见：

1. **域名出售/停放**（"域名 [xxx] 正在出售中 / is for sale"）
2. **跳转到别的站**（赌博、影视、电商、网盘、企业官网）
3. **服务器默认页 / 停运公告**（"读书业务已关停"、nginx 默认页）

超时、403、连接重置都**不算**——它们只说明"这次没拿到"。

### 3. 分组标签不是免死金牌

这 143 条"打不开"里原本有 28 条属 `成人书源` 分组，按旧规则被豁免保留。
用户明确否决：**"豁免规则也不要豁免，他就是死站了，你还豁免他干啥？"**

已执行规则变更（2026-11-19）：
- 死站判定**不看 bookSourceGroup**，一律按物理可用性处理
- 成人源只在"内容分级"意义上保留，不豁免质量判断

`成人书源` 分组仍保留，用于内容分类；但它不再是"删不删"的依据。

## 三、踩过的坑

### 坑 1：域名匹配带 www 导致漏删

`host()` 归一化会去掉 `www.`，但黑名单里写 `www.jcdf99.com` 就匹配不上，
结果第一次跑完只删了 1 条，实际该删 2 条。

**修正**：所有域名比较统一走 `norm_host()`，黑名单 `hosts` 字段也只存
归一化后的裸域名。

### 坑 2：清单做成文档，用户没法点

第一版把 158 条做成了 HTML 文档，用户反馈"文档我咋点？你发到对话里边，
我直接点链接"。

**修正**：新增 `scripts/export_review_list.py`，直接输出 Markdown 链接。
对话里贴出来即可点，比打开文件再复制粘贴快一个数量级。

### 坑 3：回复太长被截断

158 条链接一次性贴出来，回复被截断在 45 条、46 条、甚至只剩"46"。

**修正**：单条回复最多贴 2-3 组（20-30 条），分段发。

### 坑 4：黑名单 scope 用错会误伤

- `scope=host` → 整站变性（赌博/电商/企业站），拦掉该域名全部规则
- `scope=url` → 僵尸站，只拦被确认死掉的那一条规则

这 143 条用的是 `scope=url`，因为它们只是"当前打不开"，
不能证明同域其他规则也死。

## 四、沉淀下来的流程

```
集合采集 → 四层体检（URL/DNS/TCP/内容）
        → 判不出的一档走浏览器截图（12 并发，360 条 584s）
        → 截图仍判不出 → 导出可点清单交人工
        → 人工结果 → apply_review_result.py 自动清理 + 补黑名单
```

对应脚本：
- `scripts/quality_check.py` —— 四层体检
- `scripts/shot_check.py` —— 浏览器截图
- `scripts/export_review_list.py` —— 导出可点清单
- `scripts/apply_review_result.py` —— 应用人工结果

## 五、还能改进的地方

1. **浏览器层前移**：现在截图是第三道，可以提到第二道，直接把 HTTP
   判 403/超时的源丢给浏览器，减少一轮人工。
2. **人工结果反向训练**：这 158 条结论应作为黄金标注集，以后每次改判据
   都拿它回归一次，确保不倒退。
3. **判据阈值**：目前"判不出"没有明确的置信度，可以考虑给截图法的
   ink 占比、书链数量加权打分，先自动分档再交人工。
