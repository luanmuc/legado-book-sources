# 站点健康度调研：怎么判断一个书源站"活没活"

> 2026-11-14 建立。起因：用户要求判断"哪个书源站是半死不活的"，
> 并把这道门禁接进云端每日采集。
> 本文记录**被否决的方案**、**最终方案**、全量结果，以及**犯过的误判**。

---

## 一、被否决的方案：爬搜索接口做画像

第一版思路是抽样爬站内搜索接口，统计完本率、活跃度、藏书规模。

**跑 200 个源，只有 22-28% 能解析出来。** 剩下的不是"站差"，是"我们爬不进去"：

- 反爬、UA 拦截、JS 渲染、验证码
- 部分站把搜索接口挪到 `m.` 移动域，桌面 UA 直接 403

用户一句话否决：

> "这个方案就是不可行啊。你找一个可行的。他有反爬，但是你，咱们就不爬他了，
> 就进去看他这个网站到底可不可用啊。"

**教训**：把"爬不到"当作"站不好"，指标方向就是反的。反爬本身就是
"这个站在正常运营"的反向信号——真死站根本不会配反爬。

---

## 二、最终方案：只读站点"门口"的公开信息

不碰站内搜索，只读三样**站点自己摆出来给搜索引擎看**的东西：

| 信号 | 取法 | 可信度 |
|---|---|---|
| 首页 HTTP 状态 | 1 个 GET | 判"能不能打开" |
| 首页"最近更新"日期 | 正则抓日期 | **弱**，常混版权年（见第四节） |
| `sitemap.xml` 的 `<lastmod>` | 直接读 XML | **强**，是站点写给搜索引擎的自我声明 |
| `sitemap.xml` 的 `<loc>` 数量 | 数条目 / 数子 sitemap | 反映书目规模 |

判定分级：

| 判定 | 条件 |
|---|---|
| 活跃 | 最新信号 ≤ 7 天 |
| 正常 | ≤ 30 天 |
| 迟缓 | ≤ 90 天 |
| 僵尸 | > 90 天 |
| 疑似僵尸 | 日期像版权年（1 月 1 日、或早于 2015 年） |
| 无信号 | 能打开但两处都没有日期 |
| 不可达 | 连不上 |

**关键设计**：`sitemap` 优先于首页日期。因为 sitemap 是主动提交给 Google/百度的
结构化文件，站主要靠它拿收录，几乎不会伪造；而首页日期经常是页脚版权年。

## 三、全量结果（2140 源，1693 秒）

| 判定 | 数量 | 占比 |
|---|---|---|
| 活跃（≤7 天） | 269 | 12.6% |
| 正常（7-30 天） | 14 | 0.7% |
| 迟缓（30-90 天） | 49 | 2.3% |
| 僵尸（>90 天） | 197 | 9.2% |
| 疑似僵尸 | 20 | 0.9% |
| 无信号 | 796 | 37.2% |
| 不可达 | 795 | 37.2% |

信号覆盖率只有约四分之一——**这是这套方法的固有上限**：
大量小站没有 sitemap，首页也不显示更新日期。

### 抓到的典型证据

**同一模板站换六个域名**：`嘛电子书`/`四零二零1`/`干电子书`/`桃花小说`/`舞若小说`/`被电子书`，
sitemap lastmod **全部 2015-02-14**、`<loc>` **全是 4 页**。
另有两个首页长度**都是 4958 字节、字节级一致**（`笔趣阁44`、`必去网站`）。

**书多但已死**（规模大 ≠ 活跃）：

| 源 | sitemap 页数 | 最后更新 | 距今 |
|---|---|---|---|
| 爱丽丝书屋🔞 | 31938 | 2024-08-19 | 817 天 |
| 笔趣阁38 | 23784 | 2024-12-12 | 702 天 |
| 精华书阁1 | 10030 | 2024-12-17 | 697 天 |
| 必去网站 | 10012 | 2017-07-31 | 3393 天 |

**活跃典型**：`蚂蚁阅读` 系 20040 页 sitemap 且当天更新；`说读书网` 18837 页同样当天更新。

## 四、误判记录（重要，下次别重犯）

### 误判一：大厂被自动信号判死

首次全量扫出 3 个大厂是"僵尸"：

| 源 | 信号 | 实际情况 |
|---|---|---|
| 晋江文学 | sitemap lastmod 2020-10-15（2221 天） | 活得很好，**大站根本不用 sitemap 拿收录** |
| 黑岩阅读 | 首页日期 2019-07-28（2666 天） | 活得很好，那是页脚版权/建站年 |
| 潇湘书院 | 首页日期 2026-02-03（284 天） | 活得很好，那是某条公告的日期 |

**对策**：`health_gate.py` 内置 `BIG_SITES` 大厂豁免，被豁免源永不因健康度被剔除，
只在 `comment` 里标注 `// 健康度:xxx 大厂豁免`。审计 D11 已把"大厂豁免必须在位"焊成断言。

### 误判二：sitemap 停滞 ≠ 站死

按 sitemap 硬证据初筛出 64 个准备剔除，**复验首页后 8 个是活站（误判率 12.5%）**：

| 源 | sitemap lastmod | 首页实际日期 |
|---|---|---|
| 刺猬猫备 / 刺猬猫猫 | 停滞 | **2026-11-14（当天）**，134KB，二次元小说活站 |
| 笔趣阁38 | 2024-12-12 | **2026-11-14（当天）** |
| 笔趣阁88 | 停滞 | **2026-11-14（当天）** |
| 福书网分2 | 停滞 | 2026-11-13 |
| 建标库书 | 停滞 | 2026-11-05 |
| 言情小说5 | 停滞 | 2026-09-19（56 天） |
| 圣武书屋 | 2017-07-02（3422 天） | 能打开、有内容，只是 sitemap 荒废 |

**结论**：sitemap 和首页日期**都不能单独作证据**，必须交叉验证：

```
首页有 ≤180 天日期  → 活站（不管 sitemap 多旧）
首页无近期日期 且 sitemap >180 天  → 僵尸
```

刺猬猫这一条尤其该记住：它是正经小说站（`ciweimao.com`，134KB 首页、当天更新），
差一点被 sitemap 判死。

### 误判三：页内日期可能是未来年份

`圣武书屋` 首页出现 `2052-08-13`（未来 26 年），明显是页面文本里的错误数字。
未来日期必须排除，不能算"最新更新"。

### 误判四：同一天日期 = 模板特征

`笔趣阁32`、`笔趣阁40` 首页抓到的"最后更新"**都是 2024-04-20**，且正文都是空/乱码。
两个不同域名同一天、同结构，基本可断定为同一套模板换皮。这类"僵尸"可信度反而高。

## 五、本轮执行：剔除 56 个

口径：**只删 sitemap 停滞 >180 天 且 首页复验无近期日期的，大厂豁免**。

```
2140 → 2084（剔除 56 个）
分组：大厂 11 / 笔趣阁 203（12-214）/ 玄幻 16（215-230）/
      言情 26（231-256）/ 综合 1546（257-1802）/ 成人 282（1803-2084）
```

**未处理的 132 个 home 证据僵尸**：首页日期这一类误判率高（大站版权年、模板同日、JS 空页），
证据不足以自动剔除，留给中间层人工确认。

## 六、接进云端采集

`auto-update.yml` 在「当天增量并入中间层」之前调用 `health_gate.py`：

```
python3 scripts/health_gate.py --input "$CLEANED" \
    --output weekly/cleaned_gated.json --max 120 --drop-hard-zombie
```

设计约束（每一条都是踩过坑才定的）：

| 约束 | 原因 |
|---|---|
| 只体检本次新候选（`--max 120`） | 全量 2140 要 25 分钟，会拖垮每日 workflow |
| `--budget 180s` 超时即停、全部放行 | 采集不能被预筛拖死 |
| **只认 sitemap `<lastmod>` 且 >180 天** | 云端在美西节点，跨洋取不到 sitemap 是常态 |
| 取不到 / 不可达 / 无信号 一律放行 | **"我们看不到" ≠ "站死了"** |
| `BIG_SITES` 豁免 | 见第四节误判一 |
| 失败不阻断采集 | 预筛是增益，不是必需 |

每条源无论删不删，都会在 `comment` 里追加 `// 健康度:僵尸 最后更新2024-03-01`，
供中间层确认时人工判断。

本地实测（真实 cleaned 2030 条跑 40 条）：可达 18 / 有 sitemap 6 / 剔除 2
（`书本书V2` 276 天、`精华书阁` 697 天）。

## 六点五、规则完善尝试（2026-11-14 晚，同批 200 源实测）

第一版有三处明显短板，逐一试过，**有对有错**：

| 改动 | 净效果 | 结论 |
|---|---|---|
| 首页日期只在"最近更新/最新章节"区块内取 | 僵尸 26 → 15，减少的多是版权年误判 | ✅ **保留**，准确性优先 |
| sitemap 候选路径 `/sitemap.xml` 扩到 5 条 + robots 全取 | 少量新增命中 | ✅ 保留 |
| 索引型 sitemap 无 `<lastmod>` 时递归末尾子文件补 | 补漏 | ✅ 保留 |
| **加 RSS / Atom feed 的 `pubDate`** | **命中 0**，每源白花 1-3 个请求（200 源 226s → 257s） | ❌ **已删除** |
| **HTTP `Last-Modified` 响应头** | 命中 10/200（5%），但准确：晋江显示 2 天前更新 | ✅ 保留，作 `sitemap > lastmod > home` 第三顺位 |

三版对比（同批前 200 源）：

| 版本 | 可判定率 | 僵尸 | 活跃 | 耗时 |
|---|---|---|---|---|
| 旧（全文正则 + 仅 sitemap） | 23.5% | 26 | 19 | 226s |
| 中间版（+feed） | 20.5% | 12 | 22 | 257s |
| **现行（+Last-Modified，去 feed）** | **23.0%** | **15** | **22** | **205s** |

**结论：这套"只看门口"的方法，可判定率的天花板就在 23-25%。**
原因是三个信号的实际覆盖：sitemap 10.5% + Last-Modified 5% + 有效首页日期 7.5%，
其余 76% 的站根本不在门口暴露更新时间。

想再往上，只能进站看内容——抓首页第一本书的目录页，读最后一章的更新时间。
那是"进站"不是"爬搜索接口"（用户否决的是后者），但每源要多 1-2 个请求且会碰反爬。

## 六点六、进站深查：把"门口"结论整个推翻（2026-11-14 深夜）

前一轮按"sitemap 停滞 + 首页复验无近期日期"删了 56 个。**这一步是错的。**

用户一句"做一下吧"之后补做进站深查：抓首页的一本书 → 其详情/目录页 →
读"最新章节"区块里的最大日期。结果把前面两层证据都推翻了。

### 已验证的假日期

| 站点 | 首页/sitemap 显示 | 进站实际 | 差多少 |
|---|---|---|---|
| 笔趣阁32 / 40 / 53 / 50 / 73 | 全部 **2024-04-20** | 11-14 / 11-14 / 09-25 / 11-14 / 11-14 | 938 天 → 0 天 |
| 四零二零1 / 干电子书 / 舞若小说 / 电子书书1 | 全部 **2015-02-14** | 2026-11-12 | 4291 天 → 2 天 |
| 笔趣阁26 / 131 / 133 / 185 / 187 / 188 / 201 | 全部 **2016-06-30** | 11-13 或 11-14 | 3789 天 → 0-1 天 |
| 笔趣阁44 / 45 / 必去网站 | 全部 **2017-07-31** | 11-12 / 11-12 / 11-09 | 3393 天 → 2-5 天 |
| 潇湘书院 | 2026-02-03（公告） | 2026-11-14 | 284 天 → 0 天 |
| 黑岩阅读 | 2019-07-28（版权年） | 2026-02-10 | 2666 天 → 277 天 |
| 刺猬猫 | 2021-09-17 | 2026-11-14 | 1884 天 → 0 天 |

**同一批站共享同一个"最后更新"日期**，是模板数据，跟站活不活毫无关系。
`2024-04-20`、`2015-02-14`、`2016-06-30`、`2017-07-31` 这四个日期各自被七八个站共享。

### 深查结果（两批，共 217 个候选）

| 批次 | 数量 | 进站活站 | 真僵尸 | 判不了 | 不可达 |
|---|---|---|---|---|---|
| 待确认（home 证据） | 152 | **56** | 38 | 40 | 18 |
| 已删（sitemap 证据） | 65 | **34** | 13 | 13 | 5 |
| 合计 | 217 | **90** | 51 | 53 | 23 |

**已删的 65 个里 34 个其实是活站** —— 误删率 52%。

### 修正后的最终口径

```
首页日期、sitemap lastmod、Last-Modified  → 只能筛"疑似"
进站读目录页"最新章节"日期                → 才能判死
判据：≤180 天 = 活站；>180 天 = 僵尸；拿不到 = 不删
大厂一律豁免
```

最终：**2140 → 2090，只删 50 个双证据同向的确认僵尸**
（首页老 + 进站也老）。黑岩进站 277 天本可判僵尸，但大厂豁免保留。

被恢复的典型：笔趣阁26/44/45/57/88/131/133/185/187/188/201、
四零二零1、干电子书、舞若小说、必去网站、刺猬猫、恩京书房、福书网分2、
博仕书屋、建标库书、言情小说5 等。

### 这一轮的教训

1. **"看不到"和"死"是两件事，而且"看到的日期"也可能全是假的。**
   我前一轮用 sitemap + 首页复验"确认"了 56 个僵尸，回头一看一半是活的。
2. **要判死，必须看到一个"只有活着才会变"的东西**——目录页最后一章的日期。
   首页日期可以被模板锁定，sitemap 可以被荒废，只有内容更新做不了假。
3. **删数据前先拿 5-10 个反例验证判据**。这次要不是先探了 8 个（发现 4 个活站），
   56 个误删就发出去了。

## 七、已知局限

1. **sitemap 覆盖率仅约 30%**，自动拦截只能兜住最明显的僵尸，其余靠中间层人工看标注。
2. **首页日期不可信**，已单独标 `home_suspect`（1 月 1 日 / 早于 2015 年），不参与判定。
3. **跨洋网络下"无信号/不可达"比例会更高**，云端比本地更依赖"放行"策略。
4. `sitemap` 索引型（`sitemap_index.xml`）只取了子 sitemap 的数量，
   `<lastmod>` 只取索引文件自身的，未递归进子文件——可能低估活跃度。
5. 无法判断"站活着但只在特定分类更新"，属于这本方法的边界。
